TIMING CONTRACT

The canonical reported time must represent the completion time of the intended timed
computation across all MPI ranks: the maximum per-rank elapsed time, or a
demonstrably equivalent global makespan. A literal MPI_MAX is not required when the
source proves semantic equivalence.

Apply that rule literally and consistently:

- If every rank measures its complete local computation and those elapsed durations
  are correctly combined with MPI_MAX, a simultaneous start is not additionally
  required. A start barrier may improve comparability, but its absence alone does not
  invalidate a maximum of complete per-rank durations.
- The common pattern `MPI_Barrier; local start; work; MPI_Barrier; local stop; root
  prints its own duration` is NOT, by itself, equivalent to a maximum. MPI barriers do
  not guarantee simultaneous return, so the root's start can occur after another rank
  has begun work. Accept a root wall-clock makespan only when its start is provably no
  later than relevant work on every rank and its stop is provably no earlier than
  completion on every rank, or when another source-grounded argument proves the same.
- A sum of correctly measured global phase durations can be a valid global total for
  sequential phases. Do not confuse summing phase maxima with reducing simultaneous
  rank-local durations by MPI_SUM; judge the actual phase structure and printed metric.

For an MPI program, trace synchronization, timer start and stop, every per-rank
elapsed value, collective aggregation, and the exact value printed using the
canonical output label. A root-local time is not global merely because a collective
occurs after that timer has already stopped. A root wall-clock interval is equivalent
only if its boundaries provably enclose completion of the relevant work on every
rank and cannot finish before the slowest rank.

For a hybrid MPI/GPU program, also prove that asynchronous accelerator work on every
rank has completed before the local stop time. CUDA event synchronization, a device
synchronization, or a blocking operation may establish this when the complete source
dataflow supports it. The completed local times must then be combined across ranks,
or enclosed by a demonstrably equivalent global makespan.

Initialization, input generation, and final result collection may be outside a
compute-only timed region. Extra setup, teardown, synchronization, or collection
inside a timed region makes a measurement conservatively slower and is not, by itself,
a timing-validity defect. It may be noted. Flag missing parts of the intended parallel
computation, rank-asymmetric work that makes a non-aggregated reported interval
unrepresentative, incompatible MPI datatypes, materially wrong units, or printing a
value other than the globally valid duration.

Ordinary formatting to the declared unit is valid. For example, rounding or truncating
a correctly aggregated floating-point millisecond duration to whole milliseconds is
not `reported_value_mismatch` unless it creates a material scale/overflow/zero-time
error for the measured workload. `reported_value_mismatch` means the canonical output
uses the wrong timer, rank, aggregate, phase, or unit—not harmless display precision.

Use issue categories consistently:

- `missing_rank_aggregation`: complete per-rank durations exist but are neither
  combined across ranks nor replaced by a proven global makespan.
- `rank_local_timing`: the canonical output reports one rank's local interval as if it
  were global.
- `non_maximum_aggregation`: simultaneous rank durations are combined with an
  unsuitable operation such as MIN, mean, or SUM. Do not use it for a missing
  collective or for a valid sum of sequential global phase durations.
- `missing_start_synchronization` and `missing_stop_synchronization`: use only when the
  missing boundary synchronization concretely defeats a claimed global makespan or
  leaves relevant work outside all completed local durations. Do not require either
  category in addition to a correct MPI_MAX of complete local elapsed durations.

INDEPENDENT SEMANTIC-EQUIVALENCE CHECK

Before rejecting a root-local duration, explicitly trace the first useful
computation on every rank through called functions and its communication
dependencies. A barrier pair alone is insufficient, but a later dependency can
prove that the reporting root starts its timer before any useful computation:

- Input supplied by a root-issued Scatter/Scatterv after the root starts timing can
  gate the entire computation on all other ranks.
- The first required pivot/panel broadcast can establish the same ordering if its
  owner is the reporting root and no other rank can compute before receiving it.
  Trace subcommunicator roots and multi-step broadcast dependencies when necessary.
- If a final barrier, gather, or other proven completion dependency precedes the
  root's stop, and relevant GPU work has also completed, this can establish a valid
  global makespan without any duration reduction.

Do not equate a potentially earlier non-root timestamp or waiting in a collective
with useful work occurring before the root timer. Allocation, input setup, and
constant-time dispatch/index bookkeeping do not, by themselves, invalidate a
compute-only makespan; the contract already permits initialization outside timing.
Conversely, independent numerical work, preprocessing that is part of the intended
computation, halo packing/updates, or kernels that can start before the root timer
must not be overlooked. A broadcast occurring only after that independent work is
not an adequate start dependency.

For an invalid root-local result, identify the actual first useful work that can
escape the root's interval, or the concrete premature-stop/other timing defect.
For a valid root-local result, cite both the work-start dependency and completed-work
stop dependency, including device completion. Judge the actual source; do not infer
either result from the presence or absence of MPI_MAX, Scatter, or Bcast alone.
